# Pre-hardware audit, 2026-11-05

Scope: every crate and Python package in this repository at the start of the pre-hardware hardening
branch (`claude/pre-hardware-hardening`). Method: a line-by-line read of the store, bridge, package,
verifier, science and reasoning code; adversarial tests written for each suspected defect *before* the fix,
so every fixed finding below is shown failing and then passing. Nothing here was tested on robot hardware.

Severity: **High** means evidence could be lost, corrupted or wrongly accepted, or a scientific result
could be wrong without a flag. **Medium** means availability or a misleading report. **Low** means hygiene.

## Checked and found sound

- Every `unwrap()` left in non-test code is on a constant header, on serialising a value that cannot fail, or after a check that makes it infallible. The science `partial_cmp().unwrap()`s run only on values already filtered with `is_finite()`.
- Bearer-token comparison is constant-time, and tokens must be at least 32 characters. Non-loopback binds are refused without a token, and the Host header is checked against DNS rebinding.
- Package paths: `safe_rel` refuses absolute paths, `..`, `\` and `:`. A property test covers arbitrary strings.
- The verifier never panicked across 1,500 seeded byte mutations, the deletion of each file and a swap of each file with its neighbour in a signed package, and it detected every change to evidence files (`properties.rs`).
- Signatures bind both the exact body and the payload type (property test, 256 cases with random keys).
